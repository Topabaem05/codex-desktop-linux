# macOS DMG implementation plan

**Goal:** Produce a development DMG with actual macOS runtime integration.
**Spec:** ../specs/2026-09-20-macos-dmg.md
**Execution:** Inline in the authorized feature branch; no merge to main.

1. Probe current official app on a macOS runner. Verify source signature and
   record exact DMG digest/version/architecture/bootstrap contract.
2. Test and implement a bounded append-only ASAR overlay; reject duplicate JSON,
   unsafe paths, malformed ranges, unknown entry contracts and repeated patching.
3. Add all-compatible profile, policy tests and real window lifecycle integration.
   Use a native observer; restrict cache release to trusted hidden idle windows.
4. Build a native startup launcher, copied-bundle staging, integrity regeneration
   and inside-out development signing. Preserve installed app and Linux defaults.
5. Run portable tests, then native CI compilation and actual-app boot checks;
   create and remount the DMG only after those checks succeed.
6. Push reviewed changes; inspect CI and download artifact/evidence. Report the
   exact signing/platform scope, unported features and unverified memory target.

## Review focus
- Do not confuse V8 heap, physical footprint or a per-agent hard ceiling.
- Do not enable Linux-only/unfinished modules through fictitious flags.
- Do not claim new OpenAI signing, notarization, account access or permissions.
- Do not overwrite installed apps or kill unrelated processes during smoke.
- Preserve primary upstream bytes and integrity verification rather than bypass.
